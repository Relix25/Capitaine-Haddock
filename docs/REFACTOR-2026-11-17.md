## 3. STRUCTURAL IMPROVEMENTS

Les modules applicatifs n'importent plus la CLI historique. Modèles, SQLite et transport Discord ont des responsabilités propres. Les adaptateurs partagent l'objet du module canonique : configuration, objets et patches de tests ne divergent pas entre deux copies.

Les migrations SQLite sont centralisées, versionnées, transactionnelles et additives. L'initialisation depuis les constructeurs reste compatible avec les anciens consommateurs ; les migrations nommées ne sont appliquées qu'une fois. Les anciennes colonnes, reçus et événements sont conservés.

Une génération de collecte indépendante de la précision de l'horloge distingue un document vérifié, absent ou en erreur. La date d'un PDF ne reste plus confirmée sur la seule base du statut global Moodle. Les données et versions précédentes restent disponibles.

Le pipeline publie un rapport après une panne Discord et conserve l'outbox. `/actualiser` indique une livraison en attente. Le dry-run travaille sur une copie temporaire de la session dédiée ; il reste une lecture réseau authentifiée, sans modification des données d'origine.

Le téléchargement réel est borné pendant la lecture. Les octets d'un lot sont temporairement stockés dans un dossier privé, puis archivés un par un. Les correspondances de pièces jointes sont persistantes ; une correspondance historique ambiguë est signalée sans réaffecter l'ancien catalogue.
